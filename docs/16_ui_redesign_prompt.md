## Who you're working for, and on what

You're redesigning the interface of **Maṇichchilambu (மணிச்சிலம்பு)**, a bilingual (Tamil and English) web app. It's a knowledge graph of the two Tamil epics, Silappatikāram (சிலப்பதிகாரம்) and Maṇimēkalai (மணிமேகலை). It's a final-year research project. The people using it are a supervisor, Tamil literature scholars, students, and general readers who know one of the two epics.

The app's one idea, which the design has to carry: **it separates what the poem says happened from what someone in the poem only claims, orders, dreams or believes.** The headline on the home page says it: "Who did it, who only said so, and who believed them." Every design choice should make that distinction easier to see, never blur it.

## What to improve

The owner's brief: **make it user-friendly, give the different kinds of entities their own icons, make it look standard and research-based rather than like a generic AI-made site, and use fonts that are right for both Tamil and English.**

### 1. Base it on published practice, not taste

For each major change, note which of these it follows. Put the reasoning in the design note (deliverables, below).

- **WCAG 2.2, level AA:**
  - Contrast of 4.5:1 for body text and 3:1 for large text and UI parts. The current `--ink-faint` (#6F6B64 on #F6F5F3) is borderline, so check it.
  - Focus is never hidden (2.4.11).
  - Target size is at least 24×24 px (2.5.8).
  - Nothing is conveyed by colour alone (1.4.1).
  - `prefers-reduced-motion` is respected.
- **Nielsen's ten usability heuristics,** especially:
  - *visibility of system status:* loading, counts, and what a filter is hiding
  - *recognition rather than recall:* icons with labels, not icons alone
  - *consistency and standards*
- **Shneiderman's information-seeking mantra for the graph:** "overview first, zoom and filter, then details on demand". The Graph page already roughly follows it. Make the order obvious.
- **Bertin's visual variables:**
  - Encode entity class with **shape and hue together**.
  - Encode certainty (told as fact, only said, caution) with **line style**, solid or dashed, not with hue alone.
  - Keep the two encodings independent, so a reader can see both at once.
- **Gestalt grouping and a clear type scale,** for example a modular scale of about 1.2. Use fewer font sizes than now, with consistent spacing on a 4 px or 8 px grid.
- **Established design systems for reference:** IBM Carbon (data visualisation and its data-table patterns) and the GOV.UK Design System (plain labels, one thing per page, readable line length of about 60–75 characters).
  - Borrow patterns, not looks.
  - Don't copy any brand's logo, name or distinctive styling.

Avoid the generic AI-site look:
- no purple-to-blue gradients, glassmorphism or glowing cards
- no emoji used as icons
- no huge hero sections with a vague tagline
- no "✨"

This is a scholarly reading tool. It should feel closer to a good critical edition or a museum collection site than to a startup landing page. The current warm paper and copper palette is a good base, so refine it rather than replace it, unless you have a strong reason.

### 2. Typography for Tamil and English

Tamil is the primary language of the text. Treat it as such, not as a fallback.

**Tamil**
- Keep **Noto Serif Tamil** for display and verse, and **Noto Sans Tamil** for UI, or make a justified switch.
- Candidates to test: **Mukta Malar**, **Catamaran**, **Hind Madurai** and **Anek Tamil**, all on npm as `@fontsource/...`. Pick by how well they render the verse, not by name.
- Check that conjuncts and vowel signs render correctly in the actual verse. Test strings: கொ, கோ, கௌ, க்ஷ, ஸ்ரீ, ழ், and a line such as `புறஞ்சிறைப் பொழிலும் பிறங்குநீர்ப் பண்ணையும்`.
- Tamil glyphs read smaller than Latin at the same font size. Size Tamil about 5–10% larger than the English beside it, so the two look equal.
- Give Tamil more line height: 1.8–1.9 for verse, and 1.6 at least for UI. The current `[lang="ta"]` rule uses 1.85 for everything, so tune it per context.
- Never letter-space, fake-italicise or uppercase Tamil. `.eyebrow` already has a Tamil version without them (`.eyebrow:lang(ta)`). Any new style with uppercase or tracking needs one too.
- Mark every Tamil run with `lang="ta"`, so the browser picks the right font and hyphenation.

**English**
- The project uses IAST transliteration with diacritics: Maṇichchilambu, Silappatikāram, Maṇimēkalai and Kōvalan.
  - **Whichever fonts you pick must contain ṇ ā ī ū ē ō ḷ ṟ ṉ ṭ ḻ ṅ ñ ś ṣ.** Check each one; Poppins and Playfair may not have all of them.
  - Missing glyphs falling back to another font is the most common visible flaw on sites like this.
- Reasonable choices:
  - reading text: **Source Serif 4** or **Literata**
  - UI: **Source Sans 3**, **Inter** or **IBM Plex Sans**
- Pair the Tamil and English fonts so their stroke weight and x-height feel related. Noto Serif Tamil pairs well with Source Serif 4 or Noto Serif.

**For both scripts**
- Keep the number of font families and weights small. Each weight is a file the reader downloads.
- Install with `@fontsource` and import only the weights you use, in `main.tsx`. Remove any `@fontsource` packages you stop using.
- Set `font-display: swap`, and check there's no big layout jump when the fonts arrive.

### 3. Icons for entity types and other categories

Use **one** icon family for the whole app:
- Install it locally: **Lucide** (`lucide-react`) or **Phosphor** (`@phosphor-icons/react`), so the stroke width and grid are consistent.
- Draw the icons the family lacks yourself as inline SVG components, on the same 24 px grid and stroke width, so they match.

Put the icon mapping in one place, for example `web/src/lib/icons.ts` or `components/EntityIcon.tsx`, keyed by the same strings the data uses.

Every icon appears **with a text label**, or at least with an `aria-label` and a tooltip in a dense place such as the graph. Icons add recognition, they don't replace words.

**Entity classes** (`cls` in graph.json):

| Class | Nodes | Icon idea |
|---|---|---|
| Person | 94 | figure or head-and-shoulders |
| Group | 36 | several figures |
| Deity | 14 | a neutral symbol, such as a radiant circle or lamp (விளக்கு) |
| Place | 34 | map pin, or a gateway for cities |
| Object | 36 | a custom anklet (சிலம்பு) icon, since the anklet is *the* object of the epic. A generic object shape for the rest. |
| Material | 25 | a gem or ingot |
| Food | 24 | grain, a leaf, or a bowl |
| Other | 10 | small dot |

- **Deity icons must not favour one religious tradition.** The epics are Jain and Buddhist works with Hindu deities in them. Avoid a specific sectarian symbol, such as a trishul or the Om sign.
- **Kind nodes:** 60 nodes are kinds or categories (`kind: true`, often with a `broader` parent) rather than individuals. Give them a variant, for example an outlined icon in place of a filled one, so "a jewel" and "this jewel" look different.
- **Nodes in both epics:** they already get a ring on the graph. Keep that, and use the same mark everywhere else such a node is listed.

**Moods** (on every record and edge):
- The moods are asserted ("told as fact"), claimed, command, intended, predicted, address, metaphor, dreamed, conditional, wish, question and thought.
- Group them into three or four visual families, for example happened, said or claimed, wanted or intended, and imagined. Give each family an icon and a line style.
- The labels in `MOOD_LABEL` (`lib/model.ts`) are the wording. Don't change it.

**The seven link terms** (`WARRANT_NAMES` in `lib/discover.ts`):
- The terms are told as fact, only said, same one, same place only, same kind only, broader kind only, and commentary reading.
- Five of them are cautions (only said, same place only, same kind only, broader kind only, and commentary reading). They're in `CAUTION` and currently drawn dashed amber.
- Keep the caution set visibly weaker than "told as fact" and "same one".

**Other sets that need icons:**
- **Answer kinds** on Ask: answered, not stated, closest and none.
- **Graph layers:** events, material and belief.
- **The two epics:**
  - A small, consistent mark for SIL and for MAN, which you can show on songs, records and path steps.
  - Keep the hue and the label. They mustn't be the same colours as the entity classes.
- **The 24 catalogue categories** on Words (`taxonomy` in `catalogue.json`).
  - It's fine to reuse entity icons where a category matches a class, such as PERSON and PLACE.
  - Don't invent 24 unrelated pictograms.

**On the graph canvas:**
- Sigma draws nodes as circles by default. Choose one of these:
  - use a Sigma node program that can draw icons, such as `@sigma/node-image` or a custom program
  - keep circles but make the classes tell apart by shape as well as colour
- The current class colours are in `CLASS_COLOURS` in `GraphCanvas.tsx`. If you change them, check them for colour-blind separation, and keep a light and a dark value for each.
- Don't break the copper highlight for the picked link, or the dimming of the rest.

### 4. Friendliness and flow

- **Plain first steps:**
  - The home page should tell a newcomer within a few seconds what they can do, and offer three or four obvious starting points:
    - ask a question
    - follow the anklet
    - read a song
    - see who's in both epics
  - Use real examples from the data, not placeholder text.
- **The graph filter panel is long.**
  - Group it into a few sections, for example "What to show", "Whose view" and "When", with the advanced items folded away.
  - A Reset link already appears when filters are on (`isFiltered` in `GraphPage.tsx`). Make it more visible, for example "3 filters on · Reset".
- **Show which drafts are unchecked:** machine drafts and checked records need distinct, consistent badges everywhere they appear.
- **Empty and loading states:**
  - Every list that can be empty needs a message that says why and what to try next.
  - Loading needs a quiet skeleton or spinner, not a blank area. The owner reported a blank space or fade on one page that couldn't be reproduced, so make sure nothing renders invisible first.
- **Mobile:**
  - Nav, filters and the guide aside must be usable one-handed at 375 px. The filter panel can become a bottom sheet.
  - No horizontal scrolling, except deliberately inside tab bands, which already fade at the edges below 860 px.
- **Keyboard:**
  - Every control can be reached in a sensible order, with a visible focus ring.
  - Escape closes the palette and the Explore menu.
  - Tabs follow the WAI-ARIA tabs pattern: `role="tablist"` is already in place, so add arrow-key movement.
- **Motion:** small, purposeful transitions of 150–200 ms at most, and none when `prefers-reduced-motion: reduce` is set.
